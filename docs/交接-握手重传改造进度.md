## 二、步骤 11（H8 会话票）—— **已完成**

设计（决策 #87）收窄为"链路先验票"，不做 0-RTT：

- 票 = `PeerProfile`（srtt/initial_k/window/bw/min_rtt）编码成固定 **12 字节**
  TLV（type=3 = `kTlvTypePrewarm`），随 HELLO/HELLO_ACK 的 TLV 块双向走。
  布局：`ver(1)|k(1,0x0F=unknown)|srtt_ms(u16)|window_kb(u24)|bw_kbps(u24)|min_rtt_ms(u16)`。
- 两侧 `profile_for(peer)` → `encode_prewarm_tlv` → `Session::set_prewarm_tlv()`
  （**必须在 `start()` 之前**；start 之后调用会被静默忽略）。
- 建立后收端在 `session_events` 里 `peer_prewarm_tlv()` → `decode_prewarm_tlv`
  → `prewarm_.put(host_.peer_key(peer))`，供**自己**的下一次连接热启动。
- 原会话不受影响（R3-24 语义不变）。
- 只有 `EngineConfig::prewarm` 为真才挂票；畸形票一律整票丢弃 → 冷启动。

### 本轮修掉的三个真问题（都已入档决策 #87）

1. **`kPrewarmTlvLen` 写成 11，布局实为 12** → `put_le16(..., data()+10)` 越界写
   1 字节，Debug CRT 报 `HEAP CORRUPTION DETECTED`。已修正并加
   `static_assert(kPrewarmTlvLen == 1+1+2+3+3+2)` 钉死。
2. **TLV 块在构造函数里一次成型，而 `set_prewarm_tlv()` 是构造之后调的** → 票
   根本发不出去。装配点移到 `Session::start()` 内（首个 HELLO 下一个 `on_tick()`
   才出网，仍是合法窗口）。
3. **MSVC Debug CRT 的断言/无效参数是模态对话框** → 在 ctest 里没人点，测试挂到
   300s 超时，并留下锁住 exe 的进程（LNK1168 → 静默跑旧 exe）。这就是上一轮"假挂死"
   的真凶之一。已在 `tests/test_util.h` 里统一改成 stderr 输出（所有测试都包含它）。

## 六、Windows 构建/测试环境的坑（本轮再次踩到）

- `cmd //c "set VCPKG_ROOT=D:\work\vcpkg&& D:\work\fcp\build.bat Debug"` —— **必须用
  绝对路径调 build.bat**（相对名在当前 shell 下解析不到），VCPKG_ROOT 必须显式 set。
- **`fcp-client.exe` 被正在运行的进程占用会导致 Release 链接 LNK1104**。本机常有用户
  手动跑的 `fcp-client.exe`（连 VPS）和 FCP GUI 的 sidecar，**不要 kill 它们**；改用
  `ctest -C Release` 直接跑已构建的测试（`cd build/windows-x64` 再调 VS 自带 ctest.exe）。
- 跑测试前先 `taskkill //IM <test>.exe //F`，并核对 exe 时间戳，避免跑到旧 exe。
