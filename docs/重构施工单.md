## 0. 任务一句话

把 `src/fcp` 从 7,521 行（20 个 `.cc` 4,937 + 22 个 `.h` 2,584）重写到更易读的结构，
**协议、线格式、加密、FEC 算法一律不动**，行为完全等价。

## 1. 铁律（违反任何一条 = 本次改动作废）

### 1.1 不许动的东西

| 类别 | 文件 | 理由 |
|---|---|---|
| **加密原语** | `aes.*` `gcm.*` `ghash.*` `gf256.*` `random.*` | 有 FIPS/NIST 测试向量对照，改一行就要重新验证 |
| **纠删码** | `cauchy.*` `rs.*` | 与 golden 对照，等价改写不产生收益 |
| **线格式** | `hdr.h` 的 6 字节布局、`wire.h` 的字节序、`fecstat.h` 的 128 字节布局与全部 `offsetof` 断言 | 一字节变化即协议不兼容 |
| **信封格式** | `envelope.h` 的 `salt(8)|nonce(8)|tag(12)`、`kNonceLimit`、`kReplayWindow` | #26/#28/#31 的安全论证挂在上面 |
| **密钥派生** | `derive_session_key` / `derive_session_key_v7` / `derive_direction_keys` 的**计算内容** | R3-1 的唯一修复点 |
| **规格常量** | `kDupAckThresh`、`kLateGuardMaxMs`、`kTombstoneMaxMs`、`kMaxS=256`、`kMaxActiveSets=256` 等所有协议常量的**值** | 每条都对应实测 |

允许的例外：把常量从 A 文件**移到** B 文件（值不变、引用处同步更新）。

### 1.2 不许改测试断言

`tests/` 是等价性契约。具体地：

- 不许删测试函数、不许删 `CHECK`/`CHECK_EQ`、不许把断言改弱
- 不许为"让测试过"而修改 `tests/*_test.cc` 里的期望值
- **允许**为重构中被迫显式化的行为**新增**测试

如果发现某条断言确实无法在新结构下保持，**停下来报告**，不要自行决定。

### 1.3 每个阶段必须自己跑通

见 §3。没跑通不许提交。

### 阶段 1：低风险去重（预计 −300 行，风险极低）

**目标**：消除"同一事实写多遍"。纯机械改动，不改变任何逻辑。

#### 1.1 统一模运算比较

**现状**：两套语义相同、写法不同的 32 位环绕比较。

- `stream.cc:14-16`（匿名 namespace 内）
  ```cpp
  bool seq_after(uint32_t a, uint32_t b)        { return static_cast<int32_t>(a - b) > 0; }
  bool seq_at_or_after(uint32_t a, uint32_t b)  { return static_cast<int32_t>(a - b) >= 0; }
  int64_t seq_dist(uint32_t a, uint32_t b)      { return static_cast<int32_t>(a - b); }
  ```
- `hdr.h:66-69`
  ```cpp
  constexpr bool set_id_after(uint32_t a, uint32_t b) {
    const uint32_t delta = static_cast<uint32_t>(b - a);
    return delta != 0 && delta < 0x80000000u;
  }
  ```

**做法**：

1. 新建 `src/fcp/seq.h`，把三个函数移进去，全部 `constexpr`，加
   `static_assert` 钉住语义（正/负/环绕/相等四种输入）。
2. `set_id_after` 改为 `return seq_after(b, a);` 并保留在 `hdr.h`（调用点太多，
   不动签名），或直接改成 `seq.h` 里的别名——二选一，**保持 `set_id_after` 这个名字
   可用**，因为 `frame_rx.cc`/`settle.cc`/`strategy.cc`/`fecstat.cc` 共 10 处引用它。
3. `stream.cc` 删掉匿名 namespace 里的三个函数，改 `#include "fcp/seq.h"`。

**验证**：`wire_test`（4 个用例含 `static_assert` 契约）与 `stream_test`(39) 全绿。

**注意**：`seq_at_or_after(a,b)` 必须严格等于 `!seq_after(b,a)`。当前实现是
`>= 0`，在 `a-b == 0` 时与 `!seq_after(b,a)` 一致，可以安全合并；但**先写一个
`static_assert` 验证**，别只靠推理。

#### 1.2 收敛 `RxSet` → `RxSetView`

**现状**：`frame_rx.h` 里 `RxSet`（私有结构，16 个字段）与 `RxSetView`（公开结构，
同样 16 个字段）逐字段重复；`frame_rx.cc:298-325` 的 `view()` 用 16 行逐字段抄写。

**做法**：

1. 让 `RxSetView` 成为基类，`RxSet` 继承它：
   ```cpp
   struct RxSet : RxSetView {
     std::bitset<kMaxS> bad_recon;              // 只有接收端内部需要
     std::array<std::vector<uint8_t>, kMaxS> symbols;
   };
   ```
2. `view()` 简化为：
   ```cpp
   bool FrameRx::view(uint32_t set_id, RxSetView* out) const {
     if (out == nullptr) return false;
     const auto it = sets_.find(set_id);
     if (it == sets_.end()) return false;
     *out = it->second;                          // 切片拷贝，正好只拷基类部分
     return true;
   }
   ```
3. 删除 `RxSet` 里与基类重复的 16 个字段声明。
4. 检查 `frame_rx.cc` 里所有用 `set.xxx` 的地方——继承后名字不变，应该零改动。

**验证**：`frame_rx_test`(19) + `settle_test`(18) + `adv_test`(10 探针) 全绿。
`RxSetView` 的直接读者是 `frame_rx_test`、`adv_test`（3 处）与 `settle` 内部；
`RxSet` 本身是私有的，测试从不碰它——所以这次改动对测试完全透明。

**注意**：`RxSet` 被放进 `std::map<uint32_t, RxSet>`，继承后对象变大 0 字节（基类
本来就是这些字段），但**确认 `std::bitset<kMaxS>` 与 `std::array<vector, 256>` 的
对齐没变**——用 `static_assert(sizeof(RxSet) == <重构前实测值>)` 钉一次。

#### 1.3 收敛 FECSTAT 字段映射

**现状**：`settle.h` 的 `SettleCounters`（21 个字段）→ `reporter.cc:106-144` 用
18 行逐字段赋给 `FecstatPacket`。加一个字段要改两处，漏一处就是静默的 0。

**做法**：

1. 在 `reporter.cc` 加一个私有辅助：
   ```cpp
   // SettleCounters 与 FecstatPacket 同名字段的机械搬运。不追求"反射"，
   // 只把 18 行赋值收进一个函数，让"加字段"这件事只有一处入口。
   void copy_settle_counters(const SettleCounters& c, FecstatPacket* p);
   ```
2. `report()` 里那段改成一次调用。
3. **不要**引入宏或模板元编程——收益不值那个复杂度。

**验证**：`reporter_test`(7) + `session_test`(22)。`reporter_test` 应该逐字段比对
`FecstatPacket` 的内容，跑通即等价。

#### 1.4 配置单向传递

**现状**：`EngineConfig`（`src/proxy/proxy_engine.h`）→ `SessionConfig` 已有
`fill_session_config()`（`proxy_engine.cc:463`，#35③ 做的），但 `StreamConfig`
未必有同款，存在"加了字段但某一端忘记设置"的风险。

**做法**：

1. 检查 `proxy_engine.cc` 里 `SessionConfig sc;`（512、558 行附近）与
   `StreamConfig sc = conn.stream_cfg;`（587 行附近）的填充方式。
2. 若 `StreamConfig` 是逐字段手填，抽成 `fill_stream_config(StreamConfig*, ...)`，
   与 `fill_session_config` 对称。
3. 若已经是整体拷贝，**跳过本项**，不要为了对称而重构。

**验证**：`proxy_engine_test`(18) + `cli_test`(7)。

#### 1.5 删除单次使用的小函数

`hdr.h` 的 `unpack_type_k()` —— 搜一遍调用点，若确实无人使用（#35 已经删过一批），
直接删；若有人用，改成直接用 `hdr_k()`/`hdr_j()`/`hdr_type()` 三个已有的
constexpr 取值函数。

**验证**：全套 ctest。

### 阶段 2：`session.cc` 拆日志与路由（预计 −250 行，风险**中**）

> ⚠️ **本阶段是唯一有真实行为风险的**：`adv_test` 的 10 个探针（321 条断言）会
> 逐字符匹配日志输出。任何一行日志的格式改动都会让它变红。

**现状**：`session.cc` 678 行。`on_oob()` 单函数 138 行（455-592），携带 12 个
`snprintf` 与 17 处 `log()`。

**做法**：

1. 新建 `src/fcp/session_log.cc` + `session_log.h`，把**所有** FECSTAT 相关日志行
   搬进去：`FECSTAT sets=...`、`FEC ledger:...`、`FEC capped:...`、
   `FEC budget restored:...`、`FEC off:...`、`FEC sample untrusted:...`、
   `FEC sample too small:...`。
   - 签名形如 `void log_fecstat_line(LogFn log, const FecstatPacket&, ...)`
   - **逐字符复制现有格式串**，包括空格与标点。不要"顺手优化"措辞。
2. `on_oob()` 拆成三个：
   - `dispatch_handshake()`
   - `handle_fecstat()`（校验 → 喂 strategy → 记 trace）
   - `log_fecstat_line()`（调用上面搬出去的函数）
3. `on_wire()`（135-258）的两个 key epoch 分支各自独立成函数：
   `on_wire_bootstrap()` / `on_wire_data()`。

**验证**：`session_test`(22) + `adv_test`(10 探针/321 断言) 全绿。
**若 `adv_test` 变红，先看日志字符串是否多/少了一个空格。**

### 阶段 3：`stream.cc` 拆四块（预计 −350 行，收益最大）

**现状**：`stream.cc` 868 行，单文件 93 个 `if`。最大的三个函数：
`handle_ack()` 126 行、`update_window()` 90 行、`pump()` 90 行。

**拆分方案**（按职责切，不是按行数平分）：

| 新文件 | 内容 | 预计行数 |
|---|---|---|
| `stream.cc` | 构造、`write`/`close`/`abort`/`on_segment`/`on_tick`/`pump`/`emit_*`/`finish` | ~250 |
| `stream_recv.cc` | `handle_data`/`insert_chunk`/`deliver_prefix`/`emit_ack`/`rwnd_out`/`cum_out` | ~200 |
| `stream_send.cc` | `handle_ack`/`fill_holes`/`retransmit_timeouts`/`probe_zero_window` | ~200 |
| `stream_window.cc` | `update_window`/`update_srtt` + 全部 epoch 计数器 | ~120 |

**核心收益**：把 90 行的 `update_window()` 关进单独文件。它承载 #32/#33 的全部
控制律（慢启动 / ssthresh / 排队刹车 / 丢包地板），目前和 ARQ 逻辑混在一起，
改窗口策略得先读懂重传。

`handle_ack()` 126 行也拆成四条路径的函数：dup-ACK 快重、SACK 填洞、cum 推进、
RTT 采样。

**实现注意**：

1. 这些是同一个类 `Stream` 的成员函数，跨 `.cc` 拆分**不需要动头文件**——
   只要成员声明都在 `stream.h` 里即可。
2. 私有辅助（`seq_after` 等）现在在匿名 namespace，拆分后会被多个 `.cc` 使用，
   所以阶段 1.1 建 `seq.h` 是**本阶段的前置条件**。
3. `CMakeLists.txt:47` 的 `add_library(fcp ...)` 是**逐个列源文件**的（不是 GLOB），
   三个新 `.cc` 必须加进去，否则链接期才炸——而且报的是"未定义符号"，看不出是
   漏列文件。

**验证**：`stream_test`(39) + `stream_e2e_test`(7) + `soak_test` + `adv_test` 全绿，
且 `replay_tool_smoke` 逐字节不变。

## 3. 每阶段的验证流程

### 3.1 构建 + 全套测试

```bash
# Windows（本地）
cmd //c "D:\work\fcp\build.bat Debug"

# Linux（VPS / CI；需已 bootstrap vcpkg 并 export VCPKG_ROOT）
cmake -S . -B build/linux-x64 -G Ninja -DCMAKE_BUILD_TYPE=Debug -DFCP_BUILD_PROXY=ON \
  -DCMAKE_TOOLCHAIN_FILE="$VCPKG_ROOT/scripts/buildsystems/vcpkg.cmake"
cmake --build build/linux-x64
ctest --test-dir build/linux-x64 --output-on-failure
```

**基线**：32/32 通过，本地约 8.4 秒（编译另计约 3 分钟）。

### 3.2 护栏（防"靠删测试变绿"）

```bash
py scripts/test_baseline.py          # Windows
python3 scripts/test_baseline.py     # Linux
```

期望输出：

```
OK: 29 binaries, 293 test functions, 3141 CHECKs (baseline met or exceeded)
```

**出现 `FAIL ... (N removed)` 就是退化了，不许提交。** 除非该阶段确实新增了测试
二进制或测试函数，那时用 `--write` 刷新基线，并在提交说明里写清原因。

### 3.3 golden 逐字节

```bash
ctest --test-dir build/windows-x64 -C Debug -R replay_tool_smoke --output-on-failure
```

`replay_tool_smoke` 用 `--require-exact` 比对 `tests/replay_golden.jsonl`，是控制器
行为等价的最强证据。**它红了说明控制律变了**，阶段 3/5 尤其要看这条。

## 5. 遇到这些情况，停下来报告

1. 某条测试断言在新结构下无法保持 → 不要改测试，报告
2. 发现 `tests/` 里有依赖内部结构的代码（`#define private public`、`friend`）→ 报告
3. 需要修改 `协议规格.md` 或 `决策记录.md` 里的任何结论 → 报告
4. 某个"看起来该删"的代码块，删掉后 `adv_test` 变红且看不懂为什么 → 报告
5. 阶段 3 的 `replay_tool_smoke` 变红 → 立刻停，这说明控制律被改动
