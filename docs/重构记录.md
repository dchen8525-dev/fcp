# src/fcp 重构：护栏与阶段记录

> 目标：**协议与线格式不动**，只重写源码。`tests` 是等价性契约——每一步都必须
> 让 ctest 保持全绿，且**不改变测试断言的内容**。

## 0. 为什么需要护栏

ctest 全绿只证明"没坏"，不证明"断言还在"。重构中最容易发生的三种退化，全都能
让 ctest 保持绿色：

| 退化 | 症状 | 护栏 |
|---|---|---|
| 删掉一条断言 | 目标仍然 Passed | `test_baseline` 比对 CHECK 数 |
| 删掉一个测试函数 | 目标仍然 Passed | 比对测试函数数 |
| 删掉一个测试二进制 | 目标数从 32 变 31 | 比对二进制清单 |

所以 `tests/test_baseline.json` 记录的是**下限**，不是等值：允许为重构新增的
行为补测试（这是证明"这层行为以前没被断言"的方式），不允许减少。

## 2. 白盒耦合

零。测试只用公开访问器（`send_window()`、`oob_bytes()`、`bytes_acked()`、
`state()` 等），没有 `#define private public`，也没有 `friend`。这是整个重构
可以"以 ctest 为契约"的前提：测试不依赖内部结构，所以内部怎么拆都不影响它们。

## 3. 每阶段必须做的三件事

```bash
# 1) 构建 + 全套测试（本地，约 3 分钟含编译）
cmd //c build.bat Debug

# 2) 单独跑护栏，确认测试套件没缩水
py scripts/test_baseline.py

# 3) golden 逐字节不变（控制器行为等价的最强证据）
ctest --test-dir build/windows-x64 -C Debug -R replay_tool_smoke --output-on-failure
```

三项都过才提交。护栏基线**只允许往上调**，调低必须在提交说明里写清原因。
