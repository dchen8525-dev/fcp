## 1. 真实进程级对抗（第十轮）

不是单测，是真二进制 + 真 UDP。做法：起 `fcp-server --speedtest`，用 600 个源端口的
随机盐垃圾包洪泛，然后照常用 `fcp-client --speedtest` 打一次，看服务是否退化、会不会崩。

| 步骤 | 结果 |
|---|---|
| 基线测速（洪泛前） | 下行 118.55 Mbps / 上行 115.13 Mbps，`error=null` |
| 洪泛 | 600 个源端口 × 10 包 = 6000 个随机盐报文（8 B 假盐 + 随机负载），数秒内连续发出 |
| 服务端存活 | 进程未退出；日志只有预期内的 `closed: unauthenticated first datagram`；`over_budget=5616`（预认证构造预算按设计拒绝了洪泛，没有建出 6000 个会话）；`live=0`、`tomb=0`、`wrerr=0` |
| 洪泛后再测速 | 下行 91.35 / 上行 67.15 Mbps，上行 2.0% 未到达（回环 CPU 与 socket 缓冲被洪泛挤占，`acked=false` 如实报了出来），`setupMs=9`，服务端仍在服务 |
| 结论 | 洪泛不改变服务端的可用性、不泄漏会话/墓碑、不让后续合法测速失败；吞吐下降是同一进程被占满 CPU 的必然结果，且被 `acked`/`lostBytes` 如实报出 |

另：洪泛里的 6000 个假盐落在 `add_peer` 之外（服务端先按源地址分配 peer 槽，再交给引擎），
`peers_` 上限 8192、满时按 `refs==0` 轮转回收（`kPeerReclaimScan`），实测没有把 600 个源地址
钉死在表里。

## 2. 复核后不成立（免得重走）

| 候选 | 复核结论 |
|---|---|
| `reap()` 里的 `Conn&` 引用会被回调（`flush_report` → `send_`、`save_profile`、`log`）越过，重入建连重哈希后 `erase(it)` 释放错节点 | **不成立**：擦除前重新 `by_conn_.find(id)`（代码里已经写明这条），且 `in_reap_` 让重入的 `reap()` 只排队不走路；遍历用的是 id 数组的拷贝，不是表迭代器 |
| `connect_addresses()` 把 `dial_addrs_` 的 deque 引用跨 `connect_once()` 持有，同步连接成功会让引擎 reflux 并擦掉这条记录 | **不成立**：队列在调用前 `swap` 到局部，函数里只让 conn id 跨回调；剩下的地址用完再 `swap` 回表，而 `close_conn()` 会无条件 `dial_addrs_.erase(conn)` |
| DNS 结果晚于引擎的 dial 超时到达时，会用没人认领的 conn id 开出 TCP socket 并永久占住 `targets_` | **不成立**：`connect_once()` 第一句就是 `if (!engine_.has_connection(conn)) return kGone;`，`connect_addresses()` 把 `kGone` 当"已结束"直接返回，socket 根本没建 |
| bench 会话析构时的那次 FECSTAT flush 会不会打到已被回收的 peer 槽 | **不成立**：`BenchServer::Peer` 是 `sockaddr_in` 的字节拷贝（`peer_`），不是 reactor 的槽号；发送路径 `send_(peer_, …)` 用的是这份拷贝，槽被复用也不影响它发给谁 |
| `Bbr::target_window()` / `pacing_rate_bps()` 的除零 | **不成立**：`delivery_efficiency_` 被 `std::clamp(…, 0.25, 1.0)` 夹住，`min_rtt_ms()` 在 0 时回落 `cfg_.initial_rtt_ms`，而构造函数把 `initial_rtt_ms <= 0` 改成 100；`mss == 0` 也被抬成 1 |
| `Stream::insert_chunk()` 合并乱序块时的下标/迭代器 | **不成立**：合并按索引做（deque 中段 `erase` 会让所有迭代器失效，代码里已按索引避开），`removed` 精确累加所有被吃掉块的长度后再 `oob_bytes_ -=`，尾部裁剪的 `limit` 也把 `delivery_pending_` 算进去了 |

## 3. 这几轮逐条对照过的"不变量"

| 位置 | 不变量 | 结果 |
|---|---|---|
| `ProxyEngine::reap` / `finish_conn` | 任何 host 回调之后不得再解引用 Conn | 成立（回调后用 id 重新查表；`finish_conn` 后调用方不再碰 Conn） |
| `Reactor::add_peer` / `peer_retired` | 地址表只跟踪活会话，满表可回收，源地址不能钉死表 | 成立（`refs` 计数 + 64 槽轮转回收） |
| `Reactor::connect_once` | 只在引擎还认这个 conn 时才建 socket | 成立（`has_connection` 前置） |
| `Stream::handle_data` / `insert_chunk` / `deliver_prefix` | 乱序缓冲既有块数上限又有字节上限，交付点只前进不后退 | 成立（`oob_max_chunks` + `rcv_cap_ - delivery_pending_`） |
| `src/fcp/seq.h` | 所有 2³² 计数器共用同一套半窗比较 | 成立（18 条 `static_assert` 把两种写法钉死在一起） |
| `FecstatValidator::validate` | 报告键只能前进，且前进幅度有上界 | 成立（`kFecstatMaxForwardSets` 挡住"跳到未来让后续全变 stale"） |
| `Session::pmtu_handle` | 只有"实际收到的线上长度等于该 MTU 应有的长度"的探测才能抬接收上界 | 成立（比较的是信封长度，不是报文自带字段；上界被本端 `pmtu_max_mtu_` 夹住） |
| `apps/cli/cli_parse.h` | 范围检查在解析处一次做完，NaN/Inf/尾部垃圾都拒绝 | 成立（`errno`/`isfinite`/`*end` 全检查） |
| `Sidecar::stopProxy` / `onProxyFinished` | "用户主动停止"不得被报成异常退出 | **修复**（A-11，进函数即置 `proxy_stopping_`） |
