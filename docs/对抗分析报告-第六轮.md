## 1. 发现与修复

| # | 严重 | 问题 | 触发输入 | 修复 |
|---|---|---|---|---|
| E-1 | **High** | 尾部存了 SHA-256，引导器却只透传、从不校验：LZMA1_alone 本身没有校验和，传输损坏/被替换的载荷可能解出一份"自洽的坏 zip" | 改坏尾部 SHA 或改坏载荷字节 | 解压前用 CNG（`bcrypt.dll`）算压缩态 SHA-256 与尾部比对；不符即拒（实测："载荷校验和不匹配（文件损坏或被篡改）"） |
| E-2 | Medium | `MoveFileEx` 失败但另一实例已就绪时，`guard.keep = true` **不删自己的 tmp**，留下 `.tmp-<key>-<pid>-…` 孤儿；且 tmp 名只含 pid，同进程连续两次启动会打到同一个目录 | 双开 exe 首运行 | 竞态输掉时显式 `DeleteTree(tmp)`；tmp 名追加 QPC 随机段 |
| E-3 | Medium | 自身路径与启动路径都按 `MAX_PATH` 处理：从长路径目录启动，或 `%LOCALAPPDATA%` 很长时启动失败 | 超长用户配置目录 | `GetModuleFileNameW` 按需倍增；≥ MAX_PATH 时走 `\\?\` 形式打开自身、启动子进程与设 cwd |
| E-4 | Medium | 启动期提示（cli `main` 里的 `[fcp] note/warning`、`--key` 告警）**不判 `--log` 阈值**：`--log=off` 仍满屏 note，`--log=error` 压不住 info | `fcp-server --log=off` | 统一经 `say()` 判定；与运行期日志同一把尺 |
| E-5 | Low | 阈值比较在 `log_line`/`note`/cli 各写一遍，方向写反的回归没有单一落点 | — | `log_level.h` 新增 `inline constexpr bool Wanted(severity, floor)`，三处共用；`cli_test` 加 5 条断言 |
| E-6 | Low | 自检失败时 `ReportError` 弹 `MessageBoxW`：CI/无人值守机器会挂到超时 | 自检缓存缺文件 | 新增 `ReportSelftestError`：只写 `selftest.txt` 与 `launcher.log`，不弹框 |
| E-7 | Low | `launcher.log` 时间戳用 `GetTickCount64()/1000`（开机以来的秒数），排障时对不上任何时间线 | 任意启动失败 | 改 `time(nullptr)`（Unix 秒） |
| E-8 | Low | `WriteFileNarrow` 不检查短写：`.ready` 只写半截会让目录永不就绪、每次都重解；自检报告写不全也报成功 | 磁盘满/配额（`.ready` 是 16 字节，实际很难触发） | 循环写满，短即失败 |

## 2. 复核后不成立（免得重走）

| 候选 | 复核结论 |
|---|---|
| 第五轮 `QuoteArg` 仍然有错（测试夹具报告 3 组失败） | **不成立**：夹具的 `Split` 模拟器对"引号内 `\\"`"处理与 `CommandLineToArgvW` 不同。用真实 API 按真实命令行形状（`exe` + 参数）复核旧实现：9 组含反斜杠/引号/结尾反斜杠的用例往返**全部无损** |
| `CON .txt` / `NUL.dat` / `CON.` 能在深层目录绕过设备名检查并写到设备 | **不成立**：实测 `CreateFileW` 在这几个名字上都在目录里生成普通文件（Win32 只在名字完全等于设备名时才按设备解析）；A-4 的检查仍是纵深防御，保留 |
| GUI 日志窗的 `appendLog` 正则与 HTML 转义 | 不成立：`toHtmlEscaped` 在拼接前调用，`[LEVEL]` 只可能来自正则捕获组，注入面为零 |
| sidecar stderr 分帧丢最后一行 | 不成立：`onProxyFinished`/`onSpeedFinished` 都冲刷了尾部缓冲 |
