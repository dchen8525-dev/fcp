## 1. 发现与修复

### A. 引导器 `launcher.cc`

| # | 严重 | 问题 | 触发输入 | 修复 |
|---|---|---|---|---|
| A-1 | High | `Utf8ToWide` 按 `need-1` 分配、让 API 写 `need` 个字符：单个非 ASCII 字符（`need==2`）时越界写 1 个 `wchar_t` | `--log-file C:\否.txt` 之类带非 ASCII 的参数进 `append_log` | 按 `need` 分配再 `resize(need-1)` |
| A-2 | High | `ParseFooter` 用 `offset + len != total - kFooterLen` 判边界：`offset+len` 回绕到 2^64 时可能被绕过（`offset` 自身又已对 `total-kFooterLen` 校验，`len` 需同时巨大才触发） | 篡改尾部 | 改减法比较：`len != payload_end - offset` |
| A-3 | High | 条目解压走 miniz 窄字符 `fopen`：`%LOCALAPPDATA%` 带非 ASCII（中文用户名常见）时，路径按 ANSI 代码页误解，解压必挂 | Windows 中文用户名首次运行（或还原回自身） | 条目先 `extract_to_mem`（miniz 自带解压长度/CRC 校验），再用宽字符 `CreateFileW` + `WriteFile` 落盘 |
| A-4 | Medium | `SafeEntryName` 不拦 Windows 保留设备名：` churches\CON.txt` 等深层条目仍可能被当设备打开 | 篡改载荷 | 或者 `..` 一并拦：新增 `IsReservedDeviceName`（CON/PRN/AUX/NUL/COM1-9/LPT1-9，忽略扩展名） |
| A-5 | Medium | 启动参数拼回命令行时只判断"含空格就包引号"：参数里的 `"` 提前终止引号、反斜杠不转义，`arg"box` 之类会截断 | GUI 传入带引号/反斜杠的参数 | 按 `CommandLineToArgvW` 规则重写（`QuoteArg`：引号包住、`"` ↔ `\"`、引号前与结尾反斜杠翻倍）；空串写 `""` |

### B. 日志契约

| # | 严重 | 问题 | 触发输入 | 修复 |
|---|---|---|---|---|
| B-1 | Medium | `note()` 绕过 `--log` 阈值：`--log=off` / `--log=error` 下启动横幅、info 提示、stall 提示仍然写 stderr 与文件，与"stderr 与文件同一把尺"契约背离 | 服务端 `--log=error` 后仍见 `[INFO] server: fcp on …` | `note()` 复用同把尺：`severity < log_level` 直接返回 |
| B-2 | Low | 日志轮转失败告警是手拼 `LogStamp() + " [WARN] …"`（无空格分隔），与契约排版 `"stamp [LEVEL] body"` 差一个空格；GUI 无法按级别着色 | 文件被编辑器占用时轮转失败 | 改走 `LogLine(kWarn, …)` 渲染 |

## 2. 复核后不成立（留着免得重走）

| 候选 | 复核结论 |
|---|---|
| `written_total + stat.m_uncomp_size > kMaxUncompressedTotal` 首条比例失真 | 不成立：循环首条时 `written_total==0`，比较退化为单条上限，语义正确 |
| miniz `extract_to_file` 写路径截断 | 不成立之处已由 A-3 取代：问题不是截断而是"窄字符按 ANSI 代码页误解"，真实触发面比截断大（中文用户名） |
| `CleanupOld` 会删掉另一实例刚解压的 `.tmp-` 目录 | 不成立：`CacheInUse` 是按"主程序 exe 独占写打开失败"判断，`.tmp-` 目录里 exe 尚未就位时 DeleteTree 失败但目录由生命周期收（TmpGuard），不留半成品 |
